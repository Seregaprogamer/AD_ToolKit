# Если перестал работать Docker

**Сначала определи масштаб.** Если `docker info` показывает Server, переходи к `docker compose ps -a` конкретного проекта. Если не показывает — проверь движок, прежде чем менять код сервиса.

1. `docker context show`, `docker context ls`: проверь, куда смотрит клиент. Удалённый Docker и локальная systemd-служба могут относиться к разным машинам.
2. На машине демона: `systemctl status docker --no-pager`, `journalctl -u docker -b -n 100 --no-pager`. У rootless-службы используй systemctl --user и journalctl --user. Ищи первую ошибку, отметь время и свободное место через `df -h`, `df -i`.
3. Если ошибка указывает на конфигурацию, сравни изменённый файл с рабочей копией. Если причина — конфликт второго процесса на сокете, выясни владельца; не меняй права сокета вслепую.
4. После устранения причины и согласования влияния на работающие сервисы запусти остановленный демон на своём хосте. Для обычной systemd-установки: `sudo systemctl start docker`. Перезапуск уже работающего демона может прервать все проекты на хосте.
5. Проверь `docker info`, затем `docker compose ps -a`, логи нужного приложения, чтение прежней записи и новый цикл записи/чтения. Если доступа к движку на площадке не дали, передай организаторам время и точную ошибку клиента.
