# ForcAD · что подготовить до отключения сети

**SOURCE VERIFIED** — в официальном списке релизов стабильным обозначен v1.4.0. Ветка master — разработка. Описанный ниже порядок setup/start --fast опубликован в README master. Для конкретного тега сверь его README и вывод help. **NOT TESTED / REQUIRES INTERNET для подготовки:** полный стек ForcAD и наборы чекеров в этот архив не входят. Локальные заметки и их тренировочный чекер работают отдельно.

## На своей машине с интернетом

1. Подготовь Git, Python 3, venv, pip и Docker с работающим Compose. Версию Compose для выбранного релиза уточни по его CLI. Сохрани в рабочем каталоге `git clone --branch v1.4.0 --depth 1 https://github.com/pomo-mondreganto/ForcAD.git`, перейди в ForcAD и запиши `git rev-parse HEAD`.
2. Создай окружение `python3 -m venv .venv`, активируй `source .venv/bin/activate`. Для офлайн-переустановки на той же архитектуре и версии Python выполни `python -m pip wheel --wheel-dir wheelhouse -r cli/requirements.txt`, затем `python -m pip install --no-index --find-links wheelhouse -r cli/requirements.txt`. У собственных чекеров могут быть отдельные зависимости.
3. Для новой игры скопируй config.yml.example в отсутствующий config.yml. В game задай start_time, timezone, round_time и flag_lifetime. В teams пропиши адреса тренировочной сети. В tasks укажи имя локального чекера и допустимое время. Конфигурация должна соответствовать упражнениям, которые ты действительно развернул.
4. Из корня проекта проверь `./control.py --help`, затем выполни `./control.py setup` и сохрани сгенерированную конфигурацию в приватном каталоге. Upstream описывает запуск `./control.py start --fast`. Режим fast использует заготовки, но может обращаться к реестру и собирать локальные сервисы. Убедись в доступности табло по http://127.0.0.1:8080/ и прохождении проверок.
5. Проверь конкретные сервисы через `docker compose config --services` и `docker compose config --images` с тем же набором файлов/профилей и именем проекта, что использует control.py. При fast-конфигурации master использует также docker-compose-fast.yml. Среди компонентов — PostgreSQL, Redis, RabbitMQ, обработчики Celery, инициализатор и API. Теги и результирующие имена образов извлекай из выбранного checkout. Таблица работающих контейнеров `docker ps --format '{{.Names}}  {{.Image}}'` помогает найти фактически запущенные сборки.

## Что перенести

Сохрани репозиторий выбранного тега, конфигурацию, каталог своих чекеров, файлы монтирования, wheelhouse, образы игровых сервисов и платформы. Для каждого **итогового** образа сверь архитектуру и ID через `docker image inspect`. Образ с ID без понятного тега сначала пометь отдельным локальным тегом. Экспортируй итоговые теги одной командой `docker image save -o forcad-images.tar ТЕГ1 ТЕГ2`, подставив полный список, и вычисли SHA-256. Базы и тома сохрани независимо от образов.

## Проверка готовности и восстановление

На чистой копии того же Linux с отключённым интернетом создай новое venv, установи зависимости из wheelhouse, загрузи tar через `docker image load -i forcad-images.tar`. Используй тот же проект и набор Compose-файлов. Для готовых финальных образов проверь запуск `docker compose … up -d --no-build --pull never`, где многоточие означает глобальные аргументы проекта до up. Сверь табло и несколько раундов со своими тренировочными сервисами. До этой проверки автономность всей платформы остаётся неподтверждённой.

Для паузы используй `docker compose … stop`, для продолжения `docker compose … start`. Если встала очередь, посмотри статус и логи отдельного worker, брокера и БД. Если табло пустое, проверь инициализацию, часовой пояс и start_time. Если сервисы поднялись с пустой БД, сравни имя проекта и подключения томов. Команда control.py reset удаляет состояние игры и не подходит для восстановления текущего раунда.
