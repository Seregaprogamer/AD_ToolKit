# Как исследовать свой неизвестный сервис

1. Из каталога проекта посмотри `docker compose config --services`, затем `docker compose ps -a`. Найди опубликованный адрес и порт. У короткой записи `127.0.0.1:18765:8080` слева порт хоста 18765, справа порт приложения 8080. У `expose` другой смысл: внешний порт на хосте он не публикует.
2. В исходниках найди точку входа приложения, обработчик и код обращения к данным. Для учебника: `rg -n 'do_GET|do_POST|CREATE TABLE|SELECT body' 06-LAB/service.py` из корня флешки. Нарисуй на бумаге последовательность клиент → обработчик → БД → ответ и подпиши ожидаемые типы полей.
3. Определи протокол по конфигу и журналу запуска. На известном HTTP-порту лаборатории выполни `curl -si --max-time 3 http://127.0.0.1:18765/health`. Первая строка показывает HTTP-статус, Content-Type — объявленный формат, после пустой строки идёт тело. Для TLS проверь имя и сертификат.
4. Чтобы проверить один известный порт своей лаборатории без прав администратора: `nmap -sT -p 18765 127.0.0.1`. Результат open означает, что TCP-приложение приняло соединение. Чтобы проверить JSON и данные, запусти функциональный чекер.
5. Открой [учебный сетевой дамп](health-demo.pcap) и [[01-SERVICE/Wireshark|гайд Wireshark]]. Исследуй два ответа на один маршрут. В одном случае приложение само вернуло 503, поэтому диагностика начинается с его конфигурации.

Для бинарного сервиса есть [маленький ELF с исходником](modecheck.c) и [[01-SERVICE/GDB|практика в GDB]].
