# HTTP 200 есть, checker падает

| Наблюдение | Что сопоставить | Что подтвердит гипотезу |
|---|---|---|
| GET /health успешен, POST падает | Метод, Content-Type, разрешения БД, тело запроса | Тестовая запись создаётся и возвращает ID |
| Запись создаётся, но GET возвращает другой JSON | Имя и тип поля, код ответа, кодировка | Один и тот же клиент разбирает старую и новую версии |
| Новый ID читается, старый исчез | Имя проекта Compose, mount, путь к БД, миграция | Прежний ID читается без пересоздания |
| Запрос проходит с хоста и не появляется в логах во время проверки | Публикация интерфейса, объявленный адрес, маршрут, время | Запрос с согласованной клиентской точки доходит до приложения |
| Сбой только под нагрузкой | Тайм-аут, очередь соединений к БД, CPU/RAM, сообщения OOM | Задержка штатной операции укладывается в лимит чекера |

**Порядок отката:** верни код или конфиг предыдущей версии. Оставь том на месте. Затем проверь старую запись, новую запись и следующий tick. [[06-LAB/README|Практика с намеренно сломанным JSON]]
